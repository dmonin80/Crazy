При запуске выберите пользователя и введите пароль. При первом запуске новой базы задайте и повторите пароль постоянного пользователя **Администратор** (минимум 12 символов). Его имя и максимальные права нельзя изменить, отключение не допускается.

Кнопка **Пользователи** открывает отдельный справочник только для Администратора. Выберите «Новый пользователь», задайте имя и пароль, отметьте разрешённые действия галочками и сохраните. Все пользователи могут просматривать имущество. Отдельно выдаются права на импорт 1С, изменение справочников, распределение с Нулевого склада, перемещение, возврат, инвентаризацию, этикетки, экспорт XLSX, журнал действий и резервные копии. Ограничения операций проверяются сервером; экспорт XLSX формируется в клиенте и проверяется перед сохранением.

После изменения пользователя его сеансы входа сбрасываются. Для смены пользователя нажмите «Вход». Пароли хранятся как солёные хеши scrypt, в журнал пароли не записываются.

**Обновление существующей установки:** закройте программу и остановите локальный сервер, замените файлы программы, сохранив папку `data` и настройки. Запускайте `run_inventory.py` или соберите EXE через `build_windows.bat`. Существующий первый администратор переименовывается в «Администратор», пароль сохраняется; данные имущества остаются в базе. Не заменяйте рабочую базу демонстрационной базой из `examples`.

## Обновление 0.2.8: повторная загрузка выгрузки

В готовой базе откройте «Импорт», выберите новую выгрузку, проверьте данные и при необходимости сравните с базой. Нажмите «Импортировать» и подтвердите обновление. Новые коды добавляются; существующие обновляются по точному коду. Общее количество заменяется значением новой выгрузки, а не прибавляется. Свободный остаток пересчитывается с учётом созданных карточек. Отсутствующие в файле коды сохраняются. Номера карточек, размещение и история сохраняются. Наименования обновляются строго из выгрузки.

Если количество стало меньше суммы количеств созданных карточек (включая возвращённые) либо меняется единица измерения позиции с карточками, вся загрузка отменяется с указанием кода. Автоматического удаления карточек или пересчёта единиц нет. Один и тот же файл повторно не проводится. Перед загрузкой создаётся резервная копия. До обновления программы остановите сервер и сохраните копию папки data.

## Единый запуск на одном компьютере

**Запускайте `start_inventory.bat`. Сервер и клиент запускаются автоматически на этом же ПК.** Отдельный компьютер и ручной запуск `run_server.py` больше не нужны. Старые BAT-файлы `start_server.bat` и `start_client.bat` теперь также перенаправляют на единый запуск.

1. Распакуйте архив в доступную для записи папку, например `D:\AHO`.
2. Для запуска исходников установите Python 3.14 и запустите `start_inventory.bat` двойным щелчком.
3. При первом запуске BAT создаст окружение `.venv` и установит зависимости; для этой установки нужен интернет. Если окружение уже подготовлено, повторный запуск не обращается за зависимостями в интернет.
4. Программа запустит сервер в фоне, дождётся его готовности и откроет рабочее окно.
5. При пустой базе появится окно создания администратора. Введите имя, пароль минимум из 12 символов и повтор пароля. После создания вход выполняется автоматически. При отмене окно закроется; повторный запуск снова предложит настройку.
6. При следующих запусках нужно только войти под своей учётной записью. Адрес сервера вводить не требуется.

Из уже подготовленного терминала можно запустить то же самое командой:

```bat
.venv\Scripts\python.exe run_inventory.py
```

В объединённой сборке точка входа — **`AHO_Inventory.exe`**: один ярлык запускает обе части. Скрипт `build_windows.bat` теперь собирает именно это приложение. Сохраните весь каталог `dist\AHO_Inventory`, включая `_internal`; перенос одного EXE без его зависимостей не предусмотрен. Готовый EXE не требует Python на целевом компьютере. **Готовая Windows-сборка в этом архиве отсутствует: сценарий сборки ещё нужно проверить на Windows.**

## Работа локального сервера

- Сервер доступен только на `127.0.0.1`; он не открывает доступ из локальной сети.
- Обычно используется порт 8765. Если его заняла другая программа, автоматически выбирается свободный порт. Клиент получает фактический адрес самостоятельно.
- Повторный запуск использует уже работающий сервер **этой папки**, а не запускает вторую копию для той же базы.
- При закрытии рабочего окна сервер остаётся в фоне, как предусмотрено исходным ТЗ. Для полной остановки выберите **«Система → Остановить локальный сервер и выйти»** или запустите `stop_inventory_server.bat`.
- Для EXE остановка также доступна командой `AHO_Inventory.exe --stop-server`.
- После перезагрузки ПК достаточно снова открыть программу: сервер запустится автоматически. Автозапуск Windows отдельно для обычного локального использования не нужен.
- База остаётся в `data/inventory.sqlite3`, рядом с программой. Клиент обращается к ней только через сервер.
- В `local_server.json` находятся локальные настройки и секрет управления сервером. Не публикуйте этот файл; разрешения папки должны ограничивать доступ вашим пользователям Windows. В AppData и реестр программа настройки не переносит.
- Журнал запуска: `data/logs/local_server.log`. Ошибка запуска показывается в окне и не приводит к очистке базы.

## Обновление с предыдущих версий

1. Остановите старый сервер: в версиях 0.2 и новее через меню «Система → Остановить локальный сервер и выйти» или `stop_inventory_server.bat`; в версии 0.1 — Ctrl+C в консоли сервера. Закройте остальные окна клиента.
2. Сохраните отдельную копию **всей старой папки**.
3. Скопируйте новые файлы программы в ту же папку, не удаляя `data`. Демонстрационная база находится отдельно в `examples/demo_data`; не подменяйте ею рабочую базу.
4. Запустите `start_inventory.bat`. Учётные записи, карточки, номера и QR-связи сохранятся. При первом запуске новая версия автоматически обновит схему базы до версии 3 (поддерживаются исходные версии 1 и 2) и предварительно сохранит согласованную копию SQLite в `data/backups`. Если обновление не удалось, не удаляйте базу: сохраните сообщение об ошибке и копию папки.

Если обновляете готовую сборку в будущем, сначала используйте команду полной остановки, сохраните копию и заменяйте файлы при выключенном сервере. Активную программу нельзя переносить или обновлять копированием открытой SQLite.

**Проверенная среда: Linux, Python 3.12.14.** Python 3.14, Windows, BAT и EXE в этой среде не проверены. Проверены реальные локальные процессы сервера и объединённый запуск GUI в offscreen-режиме; это не заменяет испытание на Windows.

## Справочники

Нажмите **«Справочники»** в верхней панели. В одном окне открываются отдельные разделы:

| Раздел | Заполняемые сведения |
|---|---|
| Склады | Наименование основного склада / объекта |
| Подсклады / кабинеты | Наименование и основной склад |
| Ответственные лица | ФИО, необязательное подразделение |
| Поставщики | Наименование, необязательные ИНН / реквизиты |
| Единицы измерения (1С) | Просмотр исходных значений из импорта; ручное изменение не допускается |

Для заполнения войдите как администратор. Операторам и наблюдателям доступен просмотр; новые записи и исправления проверяются сервером по правам. Ответственное лицо — самостоятельная запись, не обязательно пользователь программы.

Выберите раздел → **«Добавить»** → заполните поля → **«Сохранить»**. Для изменения выделите запись и нажмите «Изменить». Есть поиск, переключатель показа архивных записей, архивирование и восстановление. Физического удаления нет. При совпадении ФИО / названия нужно явно подтвердить, что это отдельная запись. При одинаковых ФИО укажите подразделение; идентичность задаётся ID.

Нулевой склад является системным: его нельзя переименовать или архивировать. Склад с имуществом и склад с активными подскладами архивировать нельзя. Подсклад можно восстановить только после восстановления основного склада. Принадлежность подсклада основному складу после создания не меняется; перемещение имущества выполняется документом.

После закрытия справочников записи доступны в окнах распределения, перемещения и возврата. Поля **«Ответственное лицо»** и **«Поставщик»** — списки с поиском. Выберите запись из списка; произвольный текст не становится новой записью автоматически. Для новых карточек можно оставить «Не назначено» / «Не указан». При перемещении существующих карточек пункт «Сохранить текущего…» оставляет прежнюю связь. Архивные записи не предлагаются для нового назначения, но сохраняются у уже учтённых карточек.

При обновлении ранее введённые ответственные автоматически переносятся в справочник по точным сохранённым строкам. Программа не угадывает подразделение или различия людей с одинаковым ФИО. Проверьте перенесённые записи и при необходимости создайте отдельные записи и переназначьте карточки через движение. ID карточек, номера, остатки и UUID базы не меняются. Наименование и код номенклатуры по-прежнему определяются выгрузкой 1С.

Новые документы движения и снимки инвентаризации сохраняют подписи складов и выбранных записей на момент операции. При последующем переименовании справочника текущая таблица показывает новое название, а эти сохранённые снимки не переписываются. Старые документы предыдущих версий также не редактируются; отсутствовавшие в них подписи задним числом не выдумываются.

## Импорт и распределение

Версия 0.2.1 содержит новый мастер импорта. Нажмите «Импорт 1С» и выберите **исходную выгрузку из 1С**, а не ранее заполненную ведомость инвентаризации.

Мастер показывает лист, строку заголовков, четыре поля с реальными названиями колонок и предпросмотр строк. Заголовки распознаются автоматически; их можно исправить вручную. Выбирать номера колонок вслепую больше не требуется. В исходных данных подсвечены распознанные колонки.

Для предоставленной выгрузки `Выгрузка с 1С.xlsx` определены:

| Поле | Колонка Excel | Номер |
|---|---|---|
| Номенклатура | I | 9 |
| Код | H | 8 |
| Единица измерения | K | 11 |
| Количество | M | 13 |

Лист: `Лист_1`. Строка заголовков: **1**. В демонстрационном файле `examples/import_example.xlsx` заголовки находятся во второй строке, порядок колонок другой; мастер должен определить его самостоятельно.

После «Проверить данные» откройте вкладку ошибок. Каждая запись показывает номер строки, адрес ячейки, поле, исходное значение и причину. Окно можно растягивать; длинный список не выводится в бесконечном сообщении JSON. Названия и коды не изменяются. Дробные количества допускаются и не округляются; отрицательные отклоняются, пустые не заменяются нулём. Формулы в обязательных полях должны иметь сохранённый результат; формулы в посторонних колонках не блокируют импорт.

### Проверка вашего образца в версии 0.2.6

Строка **8**, ячейка **M8**, количество **9,91 л** теперь принимается без округления. Исключать её из-за дробного значения больше не требуется.

Строка **197**, ячейка **M197**, по-прежнему требует уточнения: количество отсутствует. Оно не угадывается по цене или сумме. Можно исправить исходные данные либо явно исключить только эту строку через флажок во вкладке ошибок и подтверждение исключения. Пустое значение не заменяется нулём.

Повторные строки одинаковых кодов объединяются только при одинаковых наименованиях и единицах измерения и после установки флажка объединения. При исключении только строки 197 и подтверждении объединения реальный образец даёт **416 позиций**, в том числе 9,91 л из строки 8. Это проверка источника, а не изменение вашей рабочей базы.

Ранее исключённые при первом импорте позиции сами не добавляются при обновлении программы. Повторная выгрузка остаётся сравнением и не начисляет остатки. Для проверки нового первого импорта используйте отдельную новую папку программы, сохранив старую базу.

Очевидные повторные заголовки и итоги без кода распознаются как служебные строки и показываются в счётчике пропусков. Настоящая позиция с кодом и неполными реквизитами не пропускается молча.

Для CSV в этом же окне выбираются кодировка и разделитель. Для XLSX доступен выбор листа. Кнопка **«Сравнить с базой»** показывает различия повторной выгрузки без изменения остатков. Повторное проведение первого импорта не начисляет имущество заново.

## Нулевой склад: выделение строк и кнопка «Переместить»

Вверху основного окна находятся две крупные кнопки: **«Нулевой склад»** и **«Имущество по складам»**. Они расположены выше остальных команд и переключают общую таблицу. Дублирующая кнопка Нулевого склада из панели команд убрана. Для обновления используйте «Обновить».

В таблице видны все импортированные позиции:

- наименование строго из 1С;
- исходный код и единица измерения;
- начальное количество;
- нераспределённый остаток;
- число возвращённых карточек;
- количество на других складах;
- доступно на Нулевом складе: нераспределённое + возвращённое.

Таблица поддерживает поиск, сортировку и экспорт текущего поиска в XLSX. Количества сортируются как числа. Строки с нулевым доступным остатком остаются видимыми для контроля общего количества, но переместить из них имущество нельзя.

**Клик по строке только выделяет её.** Чтобы открыть операцию, нажмите **«Переместить»**. Можно выделить несколько строк с Ctrl / Shift и перенести несколько наименований в один склад / подсклад. В окне операции:

1. Выберите **склад назначения**.
2. При необходимости выберите **подсклад / кабинет**. Показываются только подсклады выбранного склада. Можно оставить «Без подсклада» и разместить имущество прямо на складе.
3. Для каждой позиции задайте количество и **вручную введите дополнения к коду создаваемых карточек**. Целые штучные единицы получают отдельные карточки, дробное количество и количественные материалы — одну карточку на выбранное количество. Рядом показан итоговый номер. Автоматического заполнения нет; разделитель входит во введённое дополнение. Например, исходный код `00001234` + дополнение `-1` даёт `00001234-1`, а дополнение `/А-01` даёт `00001234/А-01`. При проведении создаются отдельные карточки именно с этими номерами.
4. Для возвращённых единиц откройте вкладку **«Возвращённые карточки»** и отметьте конкретные номера. Повторная выдача использует эти же карточки и QR-коды.
5. Укажите ответственного, дату документа через календарь, номер и комментарий. Поле «Этаж» находится рядом с выбором склада и подсклада и действует для новых и возвращённых единиц. Для новых карточек дополнительно можно указать примечание. При повторной выдаче пустое поле ответственного сохраняет прежнего ответственного.
6. Нажмите **«Переместить»**. Только эта команда проводит операцию. «Отмена» закрывает окно без изменений.

После успешного проведения общая таблица и карточки обновляются. Остаток повторно проверяется сервером внутри транзакции. При потере ответа окно блокирует повтор команды и предлагает проверить результат по исходному ID запроса.

Сначала создайте склады и подсклады через «Справочники», если их ещё нет. Если склад не выбран, проведение недоступно. Изменение основного склада очищает прежний выбор подсклада.

Вкладка **«Имущество по складам»** показывает индивидуальные карточки. Здесь выделяются карточки для дальнейших перемещений, возврата и формирования этикеток. При возврате карточка не уничтожается: она появляется в возвращённых единицах Нулевого склада.

Окна перемещения и возврата существующих карточек также содержат поле «Этаж», выбор ответственного и поставщика из справочников, дату через календарь, номер и комментарий документа.

## Инвентаризация и сканер

«Инвентаризация» → новая или существующая сессия → фактическое место проверки. В открывшейся ведомости доступны ручные результаты, описание находки, XLSX и завершение. «К сканированию» возвращает в главное окно.

Для сканера нужен режим USB-клавиатуры, передача полного ASCII QR и Enter. Включите подходящую раскладку/настройку сканера для передачи ASCII. Установите фокус в нижнее поле. Без выбранной сессии происходит только поиск. Сессия и фактическое место выбираются явно; быстрый режим включается отдельным флажком. Повтор, другое место и движение после начала требуют ручной проверки. Неизвестный QR не создаёт имущество. Реальный сканер в этой среде не проверялся.

## Этикетки и экспорт

Выделите карточки → «Этикетки PDF» → шаблон → сохранить PDF. Печатайте из просмотрщика на принтере клиентского компьютера с фактическим размером 100%. Пробная печать и проверка сканером обязательны на вашем оборудовании. Масштабирование драйвера может изменить размеры.

XLSX экспортирует все карточки текущего текстового поиска, а не только область прокрутки. Полный Excel-фильтр, экспорт с учётом перестановки колонок и сортировки ещё не готовы. Пользовательские строки записываются как текст, включая значения с `=`.

## Дополнительный режим: отдельный сервер и HTTPS

Этот раздел нужен только при отдельной настройке сетевого режима. Для работы на одном ПК используйте единый запуск выше. Старые `run_server.py` и `run_client.py` оставлены как дополнительные точки входа.

Для прослушивания LAN запустите сервер с `--host <IP_сервера>`. Разрешите входящий TCP-порт 8765 только нужным компьютерам в брандмауэре. Не размещайте SQLite на общей сетевой папке и не открывайте её клиентами.

Для HTTPS получите сертификат вашей организации, содержащий DNS-имя сервера в SAN, и ключ. Запустите:

```bat
.venv\Scripts\python.exe run_server.py --host 0.0.0.0 --cert D:\certs\server.pem --key D:\certs\server.key
```

В настройках подключения укажите `https://имя-сервера:8765`. Для собственного центра сертификации добавьте в `client_settings.json` поле `"ca_file": "D:/certs/company-ca.pem"`. Проверка сертификатов остаётся включённой. Ключ сервера защитите правами Windows. Обычный HTTP используйте для локального испытания; в LAN пароли и токены должны передаваться по HTTPS.

Для автозапуска в Планировщике заданий Windows создайте задачу при запуске компьютера: программа — полный путь к Python окружения или AHO_Server.exe, аргументы — `run_server.py --host <IP>` (для EXE без имени скрипта), рабочая папка — папка программы. Для сетевого сервера выберите запуск независимо от входа пользователя и учётную запись с нужными правами. Этот сценарий ещё не проверен на Windows.

## Резервные копии и перенос

До импорта автоматически создаётся согласованная копия SQLite через Backup API. Администратор также может вызвать `POST /backup` через авторизованный `/docs`. Это **копия базы**, а не полный архив сервера: исходные файлы и настройки копируйте вместе со всей папкой после остановки сервера. Автоматическое расписание/срок хранения и мастер полного восстановления ещё не реализованы.

Для переноса остановите сервер, скопируйте всю папку, запустите на новом компьютере, обновите адрес клиентов и задачу автозапуска. UUID сохраняются; QR не зависит от адреса.

Для ручного восстановления остановите сервер, сохраните всю текущую папку отдельно, проверьте копию командой `python verify_backup.py <путь_к_копии>`, затем замените `data/inventory.sqlite3` выбранной копией. Только в остановленной и отдельно сохранённой базе удалите оставшиеся `inventory.sqlite3-wal` и `inventory.sqlite3-shm`, если они существуют. Не выполняйте замену открытой базы. После запуска проверьте список карточек и старый QR. Предпочтительно восстановить в отдельной папке и проверить до переключения пользователей.

## Этаж при перемещении — версия 0.2.4

В окне перемещения выберите склад / подсклад и заполните **«Этаж»**. Значение сохраняется в каждой перемещаемой карточке и показывается в одноимённой колонке вкладки **«Имущество по складам»** после обновления таблицы. Поле работает при первом распределении, выдаче возвращённых карточек и последующих перемещениях между складами.

Этаж — текст: допустимы `1`, `2`, `цоколь`, `технический`. Программа не угадывает его по номеру кабинета. При групповом перемещении введённый этаж применяется ко всем выбранным карточкам. Пустое поле в новом окне операции очищает этаж; это удобно, например, при возврате на Нулевой склад. Укажите актуальное значение для нового места. История движения сохраняет этаж до и после операции, номер и QR-код карточки не меняются.

Этаж хранится в карточке имущества как реквизит размещения. Повторный импорт для сохранения этажа не требуется.

## Дополнения к коду и верхние кнопки — версия 0.2.5

При первом распределении с Нулевого склада программа запрашивает, **что добавить к исходному коду**. Для каждой перемещаемой единицы есть пустое поле в таблице; номер строки не является автоматически присвоенным суффиксом. Введите дополнение сами, включая нужный разделитель. Итоговый номер составляется только как `исходный код + введённое дополнение`, без автоматически добавленного `/` или цифр.

Пустые дополнения, пробелы в начале / конце и управляющие символы не допускаются. Итоговые номера должны различаться между собой и не совпадать с уже существующими номерами во всей базе, в том числе у возвращённых карточек. Проверка проходит на сервере внутри общей транзакции. Если есть ошибка, карточки и движение не создаются частично.

Уже присвоенные номера не изменяются. Повторная выдача возвращённых карточек использует существующие номера и QR-коды. Повторный импорт для ручных дополнений к коду не требуется.

## Дробные количества и групповой перенос — версия 0.2.6

Количество вводится с точкой или запятой: `9,91`, `0.35`. Допускаются дробные значения как в файле 1С, так и в окнах программы, в том числе для единицы `шт`. Отрицательные значения, NaN и бесконечность не допускаются. Точность одного значения — до 30 знаков до и после запятой; превышение предела отклоняется, а не округляется.

Данные сохраняются десятичными строками, вычисления выполняются точной десятичной арифметикой. В таблице показано реальное количество карточки. Для метров, литров, килограммов и других количественных единиц создаётся карточка партии с выбранным количеством. Для целых штучных позиций сохраняется создание индивидуальных карточек. Наименование, исходный код и единица из 1С остаются без изменения; единицы не смешиваются.

**Перемещение нескольких наименований:** выделите строки Нулевого склада с Ctrl / Shift → «Переместить». Выберите общее назначение и этаж. По вкладкам кодов заполните количества и ручные дополнения, либо выберите возвращённые карточки. Общие дата, номер, ответственный и поставщик применяются к списку. «Переместить весь список» создаёт один документ и выполняет всё в одной транзакции. При ошибке в любой позиции весь перенос отменяется.

**Перемещение части количества:** во вкладке «Имущество по складам» выделите карточку и нажмите «Переместить». В таблице окна задайте, сколько переносится. Если переносится меньше имеющегося, введите дополнение к исходному коду для новой карточки отделяемой части. У исходной карточки останутся прежние ID / номер / QR и остаток на старом месте. Отделённая часть получит новую карточку с указанным номером в месте назначения. При переносе полного количества прежняя карточка перемещается целиком.

В XLSX обычные дробные количества записываются числами. Значения с более чем 15 значащими цифрами экспортируются текстом, чтобы ограничения точности Excel не меняли их. В базе и интерфейсе точность сохраняется. Для количественных карточек текущая инвентаризация проверяет наличие карточки партии; отдельный ввод фактически измеренного объёма пока не реализован.

При обновлении схема переходит в версию 3 с предварительной копией SQLite. Старые карточки сохраняются с количеством 1, прежние номера и QR-коды продолжают работать. Для отката к старой версии используйте копию до обновления.
