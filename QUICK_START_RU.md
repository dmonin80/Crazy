# АХО — Инвентаризация 0.3.0

Обновлённый проект с графическим клиентом PySide6 и сервером FastAPI/SQLite.
Это исходный выпуск: Python-зависимости устанавливаются при первом запуске.
Windows EXE в архив не включён; скрипт его сборки — `build_windows.bat`.

## Быстрый запуск на одном Windows-ПК

1. Установите 64-разрядный Python 3.12 или 3.14 с Python Launcher (`py`).
2. Распакуйте архив в локальную папку, например `D:\AHO_Inventory`.
3. Запустите `start_local.bat`. При первом запуске автоматически создаётся
   `.venv` и устанавливаются закреплённые зависимости; нужен доступ к PyPI.
4. Создайте пароль администратора длиной не меньше 12 символов.
5. Войдите как **Администратор** и импортируйте выгрузку XLSX/CSV.

`start_local.bat` явно выбирает локальную базу, даже если рядом есть `network.json`.
Клиент закрывается независимо от сервера. Для завершения сервера используйте
меню **Система → Остановить локальный сервер и выйти** или
`stop_inventory_server.bat`.

## Linux / запуск командами

Проверено на Python 3.12.14. Требуются системные библиотеки Qt для графического
окружения; без экрана тесты используют `QT_QPA_PLATFORM=offscreen`.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run_inventory.py --local
```

Не используйте `examples/demo_data` как рабочую базу. Она сохранена из исходного
архива и содержит только пример. Рабочая база создаётся в `data/`.

## Общая база в сети

1. На основном ПК выполните `setup_windows.bat`, затем `start_network_server.bat`.
2. На остальных ПК используйте сетевой клиент: `start_network_client.bat`.
   Для исходной версии сначала подготовьте `.venv` командой `setup_windows.bat`
   в локальной копии программы на каждом ПК.
3. Укажите фактический адрес сервера в `network.json`.
4. Сервер и файл SQLite должны находиться на локальном диске основного ПК.
   Клиенты работают через API и не открывают SQLite по сетевой папке.

В исходном `network.json` сохранён адрес `http://pc00527:8765` для совместимости.
Если ваш сервер называется иначе, измените его. При HTTP-подключении через сеть
программа постоянно предупреждает об отсутствии шифрования.

Для рабочих сетевых данных настройте HTTPS-прокси перед сервером:
`Caddyfile.example` и `network.https.example.json` содержат примеры.
Замените пример имени узла, сертификата и ключа своими значениями.
`company-ca.pem` нужен только при внутреннем центре сертификации.
Закрытый ключ остаётся на сервере/прокси; его нельзя класть в общую папку клиентов.
Проверка TLS всегда включена. Сертификат и доверие на ваших ПК этот архив
автоматически не создаёт. Если HTTPS-прокси находится на том же ПК, используйте
локальный сервер АХО и разрешайте клиентам доступ к HTTPS-прокси, а не к порту 8765.

## Обновление с 0.2.12

1. В старой программе создайте резервную копию. Завершите клиентов и сервер.
2. Сохраните всю старую папку программы отдельно, включая `data/`.
3. Распакуйте 0.3.0 в новую папку. Перенесите **свою** папку `data/` и свой
   `network.json`. Не заменяйте базу демонстрационной.
4. Выполните `setup_windows.bat` и запустите нужный режим.
5. Для сетевого режима обновите и сервер, и клиенты до 0.3.0.

Схема учёта совместима с 0.2.12: карточки, номера, история и UUID базы сохраняются.
Старый сервер должен быть остановлен перед запуском нового.
Настройки колонок, фильтры и идентификаторы незавершённых запросов сохраняются
в пользовательских настройках ОС, а не в общей папке программы.
Пароли, токены и содержимое импортов в этих настройках не сохраняются.

## Новые возможности

- «Разделы»: остатки, имущество, инвентаризации, документы, справочники.
- Карточка имущества: сведения, QR-код, история и печать этикетки.
- Таблица на модели Qt; точная числовая сортировка, выбор колонок,
  сохранение их порядка и ширины, активные и сохранённые фильтры.
- Экспорт учитывает текущую сортировку, порядок и видимость колонок.
- Отдельный экран инвентаризации: сканирование, прогресс, расхождения,
  ручные отметки, находки и экспорт с понятными названиями мест.
- Журнал документов и печатная форма PDF.
- Состояние соединения и время последнего успешного обновления.
- «Сервис → Незавершённые операции»: проверка результатов потерянных ответов.
  Повторяйте исходное действие с теми же данными: прежний ID предотвращает
  повторное проведение. Запись «не подтверждено» не означает отмену операции.
- «Сервис → Резервная копия» создаёт копию на сервере.

## Ограничения импорта

До 20 МБ на исходный файл, 100 МБ после распаковки XLSX, 100 000 строк и
256 колонок. Лишнее форматирование далеко за пределами данных листа нужно удалить.
Перед импортом показываются количества новых, изменённых и отсутствующих позиций.
Отсутствующие в новой выгрузке позиции автоматически не удаляются.

## Проверка резервной копии и тесты

```sh
python verify_backup.py путь_к_копии.sqlite3
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Проверка копии восстанавливает её во временную базу, проверяет связи, UUID,
карточки и QR-ссылки. Текущая база и сам файл копии не заменяются.

Результаты проверки выпуска и ограничения платформы: `docs/RELEASE_0.3.0_RU.md`.
Новые снимки интерфейса: `examples/main_window.png`, `asset_card.png`,
`inventory_workspace.png`, `documents.png`.
